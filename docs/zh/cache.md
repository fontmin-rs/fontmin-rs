# 缓存语义

Rust CLI 与 Node.js pipeline 默认都使用
`node_modules/.cache/fontmin-rs`，但会维护各自的缓存条目与 runtime identity。
缓存默认关闭；公开配置项请查看[配置文件](./guide/config)。

## 一致性

每个带版本号的缓存根目录同时只允许一个写入者。写入者以独占方式创建带 owner
标识的锁，通过临时路径写文件，再以原子替换提交完整文件。因此多个进程会串行更新
缓存，不会同时修改索引或同一个条目。

锁释放会核对 owner：写入者只移除自己取得的锁，延迟清理不会误删后继写入者的锁。
读取端会把不完整或缺失的条目视为 cache miss，并重新构建。

## 进程终止与取消

正常完成和返回错误都会释放锁。Rust 进程内的缓存写入任务被取消时，任务释放锁对象
也会同步释放对应的锁。

如果进程在写入期间终止，下一个写入者会识别记录的进程已结束并立即接管。对于旧格式
或无法解析的 owner 标识，仍保留五分钟的时间兜底。恢复期间，新的写入者会先清理版本
缓存树中遗留的 `*.tmp` 临时文件，再开始更新。Rust 任务取消也会在释放锁时执行同样的
清理。

取得锁的重试窗口约为五秒。超时通常表示仍有其他存活写入者持有锁，或者缓存位于无法
验证本机进程 owner 的文件系统上。

## 运行边界

该锁协议面向同一主机上的独立进程。不要让不同机器通过网络文件系统共享同一个可写
缓存目录，因为进程编号只在本机有效。每台机器应使用独立缓存目录，只共享不可变的构建
产物。
